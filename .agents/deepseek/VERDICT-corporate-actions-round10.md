## Blocking findings

1. **[notebooks/refresh_bronze_corporate_actions.py:503-505] CLI mode reads the Massive key via `ws.secrets.get_secret(...).value` and never base64-decodes it.**
   Confirmed by inspection of the installed `databricks.sdk`: `SecretsAPI.get_secret` docstring states the returned `value` is "the value of the secret in its byte representation" and "the secret value returned is in bytes"; `dbutils.secrets.get()` (notebook mode) base64-decodes to plaintext, but the raw SDK returns the base64-encoded bytes as a string. A repo-wide search for `base64`/`b64decode` finds **no decode anywhere** in `notebooks/refresh_bronze_corporate_actions.py` or `etl/corporate_actions.py`. The adapter then sends that base64 string verbatim as `apiKey=`, so every CLI-mode request (runbook §2–3, any `spark_python_task`/local `python ...` invocation that falls through the SDK path) returns 401. Notebook-mode (`dbutils.secrets.get`) is unaffected and returns plaintext, which is why the scheduled `notebook_task` in `resources/jobs.yml:23` works but the CLI path does not.
   → Fix requires `import base64; massive_api_key = base64.b64decode(raw).decode("utf-8")` on the SDK branch (and no decode on the `MASSIVE_API_KEY` env-var branch, which is already plaintext). This is pre-existing (introduced at c2b844f, not a round-10 regression), but it is a live, confirmed 401 and blocks the lane's documented CLI path.
